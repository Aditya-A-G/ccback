# ccfind — original v1 design notes

> Historical. This is the design the first version was built from, under the working name `session-finder`. The command-line grammar, the mode switcher and the opt-in semantic search described here were all replaced during review. `README.md` describes how ccfind behaves today; this file is kept for the reasoning behind the data model, ranking and security rules, which still hold.

## Problem

Claude Code users run sessions in many folders. They remember a topic ("how I will record videos and how Claude will edit them") but not which folder the session lived in. Claude Code stores all transcripts under one directory, so a local tool can search them all and answer: which session, in which folder, and how do I get back into it.

## User flow

1. User runs `session-finder "recording and editing videos"` (or bare `session-finder` for a live search box).
2. The index updates incrementally (first run: a few seconds), then results appear: sessions, best first, each with title, real folder path, last-active date, git branch, match count and a highlighted snippet.
3. User presses Enter on a result. The tool exits the UI and runs `claude --resume <sessionId>` with the working directory set to that session's folder. Ctrl+Y copies `cd '<cwd>' && claude --resume '<sessionId>'` instead.
4. `session-finder web` serves the same search on `http://127.0.0.1:<port>` with filters, a mode toggle and a transcript reader.

## Data source (verified on a real machine)

- Root: `$CLAUDE_CONFIG_DIR/projects` if the env var is set, else `~/.claude/projects`. Overridable with `--projects-dir`.
- Layout: `<root>/<encoded-cwd>/<sessionId>.jsonl`. **Only files at exactly this depth are sessions.** Nested `<root>/<encoded-cwd>/<sessionId>/subagents/*.jsonl` are subagent transcripts and are **never indexed**.
- The encoded directory name is lossy (both `/` and real `-` become `-`). **Never derive the folder from the directory name.** Use the `cwd` field of the first indexable `user`/`assistant` record. If a session has no such record, skip the session.
- One JSON object per line. Files are appended to while a session is live, and a final line may be partial. Malformed lines are skipped silently.
- Record types seen: `user`, `assistant`, `ai-title`, `attachment`, `system`, `mode`, `permission-mode`, `file-history-snapshot`, `queue-operation`, `last-prompt`, `continued-in`, others. Unknown types are ignored.
- Title: the **last** `{"type":"ai-title","aiTitle":"..."}` record. Fallback: first 80 chars of the first indexed human message. 
- Useful fields on `user`/`assistant` records: `uuid`, `timestamp` (ISO), `cwd`, `gitBranch`, `isSidechain`, `isMeta`, `message.role`, `message.content`.

### What counts as an indexable message

- `type` is `user` or `assistant`, `isSidechain` is not true, `isMeta` is not true.
- `message.content` is a string, or an array of blocks. From arrays keep only blocks with `type == "text"`, joined with `\n`. Ignore `tool_use`, `tool_result`, `thinking`, `image` and anything else.
- Clean the text: remove `<system-reminder>…</system-reminder>` blocks (multiline). Drop the message entirely if, after cleaning, it is empty or is harness noise: starts with `<command-name>`, `<command-message>`, `<local-command-stdout>`, `<local-command-stderr>`, `<task-notification>`, `<bash-input>`, `<bash-stdout>`, or `Caveat: The messages below were generated by the user while running local commands`.
- Stream files line by line (`readline`). Never read a whole file into memory. Real data: 790 MB total, single files of tens of MB.

## Architecture

TypeScript, Node >= 20, ESM, compiled with `tsc` to `dist/`. One shared core, thin front ends.

```
src/
  core/
    paths.ts        resolve projects dir + index dir
    parser.ts       stream one .jsonl -> { session meta, messages[] }
    db.ts           open/migrate SQLite (better-sqlite3), schema version
    indexer.ts      incremental sync of all sessions into the DB
    query.ts        natural sentence -> search terms (stopwords, FTS5-safe)
    keyword.ts      FTS5/BM25 search -> ranked sessions
    embedder.ts     Embedder interface + transformers.js implementation (lazy import)
    semantic.ts     build embeddings, vector search -> ranked sessions
    hybrid.ts       reciprocal rank fusion
    search.ts       single entry point: search(opts) -> SessionResult[]
    resume.ts       build resume command, spawn claude
  cli.ts            arg parsing, subcommands, non-interactive output
  tui/              Ink app                     (phase 2, separate agent)
  web/              http server + static page   (phase 2, separate agent)
test/               vitest + fixtures
```

Dependencies: `better-sqlite3`, `ink` + `react` (TUI), and `@huggingface/transformers` as an **optionalDependency**, imported only via dynamic `import()` when semantic features are used. The web server uses `node:http` only. The web page is a single static HTML file with vanilla JS, no build step, no CDN.

Index location: `~/.session-finder/index.db`, overridable with `SESSION_FINDER_HOME`. Model cache: `~/.session-finder/models`.

### Schema

- `files(path PRIMARY KEY, session_id, mtime_ms, size)`
- `sessions(id PRIMARY KEY, cwd, title, git_branch, first_ts, last_ts, message_count, file_path)`
- `messages(id INTEGER PRIMARY KEY, session_id, uuid, role, ts, text)` with index on `session_id`
- `messages_fts` — FTS5, external content on `messages(text)`, `tokenize='porter unicode61'`
- `chunks(id INTEGER PRIMARY KEY, message_id, session_id, text, embedding BLOB)` — Float32 little-endian, L2-normalised
- `meta(key, value)` — schema version, embedding model id + dims

### Incremental indexing

- Walk the projects dir. For each session file compare `(mtime_ms, size)` with `files`. Unchanged: skip. New or changed: inside one transaction delete that session's messages, FTS rows and chunks, then re-parse the whole file and insert.
- Files in `files` that no longer exist on disk: remove the session and all its rows.
- Every search command syncs first (fast when nothing changed). `--no-sync` skips it. `session-finder index` syncs explicitly and prints counts. `--rebuild` drops everything first.
- A changed session loses its chunks, so its embeddings are rebuilt on the next semantic sync.

### Keyword search

- `query.ts`: lowercase, split on non-alphanumerics, drop a small English stopword list, de-duplicate. If every word is a stopword, keep them all. Build an FTS5 query by OR-ing the terms, each wrapped in double quotes so user punctuation and FTS5 operators (`"`, `*`, `-`, `AND`, `NEAR`, `:`) can never produce a syntax error. Porter stemming comes from the tokenizer, so "recording" matches "recorded".
- Fetch the top 500 messages by `bm25(messages_fts)` (after filters). Convert to positive scores. Multiply each message's score by the number of **distinct query terms** it contains (coverage), so a message with `record`+`edit`+`video` beats one that repeats `video` alone.
- Session score = sum of its top 3 message scores. Sort descending, tie-break by `last_ts` descending.
- Snippet: FTS5 `snippet()` of the best message with sentinel markers, returned as structured `{text, highlights: [start,end][]}` so each front end styles it itself. Never return HTML from the core.

### Semantic search (opt-in)

- `Embedder` interface: `{ id: string; dims: number; embed(texts: string[]): Promise<Float32Array[]> }`. The real implementation uses transformers.js `feature-extraction` with `Xenova/all-MiniLM-L6-v2` (quantized, 384 dims, mean pooling, normalised). Tests inject a deterministic fake embedder. **Tests must never download a model or touch the network.**
- Chunking: split each message into chunks of about 800 characters on paragraph/sentence boundaries, at most 6 chunks per message, skip chunks under 20 characters.
- `session-finder index --semantic` embeds every chunk whose `embedding` is NULL, in batches of 32, with a progress line on stderr. It is resumable: interrupting and re-running continues where it stopped. If the stored model id differs from the current one, all embeddings are cleared first.
- Search: embed the query, brute-force dot product against all chunk vectors (loaded into one contiguous Float32Array, cached per process, invalidated when the DB changes). Message score = its best chunk. Session score = mean of its top 3 message similarities. Snippet = the best chunk's text, truncated to about 240 chars, no highlights.
- If `@huggingface/transformers` is not installed, or no embeddings exist, semantic/hybrid modes fail with one clear actionable message (`Run: session-finder index --semantic`), exit code 2. Keyword mode never depends on any of this.

### Hybrid

- Run keyword and semantic, each producing up to 50 ranked sessions. Fuse with reciprocal rank fusion: `score = Σ 1/(60 + rank)`. Prefer the keyword snippet when the session appears in the keyword list. Each result carries `sources: ("keyword"|"semantic")[]` so the UI can show why it matched.

### Core API

```ts
search({ query, mode: 'keyword'|'semantic'|'hybrid', limit?, cwdPrefix?, since?, until?, role? })
  -> Promise<SessionResult[]>

SessionResult = { sessionId, title, cwd, cwdExists, gitBranch, firstTs, lastTs,
                  messageCount, matchCount, score, sources,
                  snippet: { role, ts, text, highlights } , resumeCommand }
```

- `resumeCommand` is `cd '<cwd>' && claude --resume '<sessionId>'` with POSIX single-quote escaping of both the path and the id (paths may contain spaces and quotes).
- Filters: `cwdPrefix` matches the folder or anything under it, `since`/`until` are ISO dates compared with message `ts`, `role` is `user` or `assistant`.

### CLI

```
session-finder [query...]           interactive TUI (phase 2). Until the TUI exists, prints results.
session-finder search <query...>    non-interactive, prints results.  --json for machine output
session-finder index [--semantic] [--rebuild]
session-finder web [--port 4777] [--no-open]
session-finder stats                sessions, messages, chunks embedded, index size, projects dir
common flags: --mode keyword|semantic|hybrid (default keyword), --limit N (default 10),
              --cwd <path>, --since <date>, --until <date>, --role user|assistant,
              --projects-dir <path>, --no-sync
```

Plain output per result: title, folder (marked `(folder missing)` if it no longer exists), date, branch, match count, snippet, resume command. Colour only when stdout is a TTY and `NO_COLOR` is unset. Exit codes: 0 ok (including zero results), 1 unexpected error, 2 usage/setup error.

## Phase 1 acceptance criteria (core + CLI)

1. `npm run build` and `npm test` pass with exit code 0. `npx tsc --noEmit` is clean under `strict`.
2. Subagent files under `<sessionId>/subagents/` are never indexed, proven by a fixture.
3. A fixture whose real cwd contains dashes (`/tmp/my-cool-app`) is reported with the exact `cwd` from the record, not a path decoded from the directory name.
4. String content and block-array content both index. `tool_result`, `thinking`, `isMeta`, `isSidechain`, system-reminder text and harness-noise messages are not searchable.
5. A truncated last line and random garbage lines do not crash indexing, and the other messages in that file are still indexed.
6. Second sync with no changes re-parses zero files. Appending to a file re-indexes only that session. Deleting a file removes the session from results.
7. Ranking: a message containing all of `record`, `edit`, `video` once outranks a session that repeats only `video` many times. "recording" finds "recorded".
8. Queries with FTS5-hostile input (`"`, `*`, `foo:bar`, `AND OR NOT`, `-x`, emoji, empty string, only stopwords) never throw. Empty query returns an empty list.
9. Filters (`cwdPrefix`, `since`, `until`, `role`) each change results as expected. `cwdPrefix` `/a/b` must not match `/a/bc`.
10. Semantic and hybrid work end to end with the fake embedder, including resumable embedding and model-id change invalidation. RRF has a direct unit test. Without embeddings, semantic mode gives the actionable error and exit code 2.
11. `resumeCommand` is correctly quoted for a cwd containing a space and a single quote.
12. `search --json` emits valid JSON matching `SessionResult[]` and nothing else on stdout (progress and warnings go to stderr).
13. Smoke test against the real `~/.claude/projects` on this machine (read-only): `node dist/cli.js search "how I will be recording the videos and how you will be editing the videos"` returns results in under 5 seconds on a warm index, and the top 5 include a session whose cwd ends with `/dashboard` or `/Documents/test`. Report the actual output and timings.

## Phase 2a — Terminal UI (`src/tui/`, Ink)

Positioning from research: Claude Code's own `/resume` crosses folders but only matches title/first message; the most popular third-party picker (ccresume) has no search box; the tools with real search have no picker or preview. We are: search by what was said, preview before committing, one key to get back in.

```
 › recording videos█                          keyword ▸ Tab
 ────────────────────────────────────────────────────────────
 ▸ Storyboards repos comparison      ~/…/dashboard      10d
   Interview prep and transcripts    ~/Documents/test   10d
 ────────────────────────────────────────────────────────────
 You · Sep 10
 "…I can [record] with OBS, screen [recording] with my voice…"
 ────────────────────────────────────────────────────────────
 ⏎ resume   c copy command   o open in browser   esc quit
```

- `session-finder` with no args opens it; `session-finder <query>` opens it pre-filled. When stdout is not a TTY, fall back to the plain `search` output.
- First run: one status line `Indexing 376 sessions…` then `done in 3.1s`. Later runs show the box immediately and sync in the background of startup (sync must finish before first results render, but must not block drawing the box).
- Empty query lists the most recent sessions (by `last_ts`), so the tool is useful before typing.
- Search as you type, debounced about 120 ms, stale results discarded. ↑/↓ and Ctrl+P/Ctrl+N move; the list scrolls; selection never jumps off screen.
- Row = title (truncated), folder with `$HOME` as `~` and middle-elided to fit, relative age. Nothing else. Preview pane underneath shows role, date and the snippet with highlights in bold/colour, wrapped to width. Layout adapts to terminal width and height, and survives resize. Minimum useful size 60x15.
- Enter: unmount Ink, restore the terminal, then spawn `claude --resume <id>` with `cwd` = session folder and `stdio: 'inherit'`, exiting with its code. If the folder no longer exists: do not spawn; show `Folder no longer exists: <path>` with `o` to read it in the browser and `c` to copy the id. If `claude` is not on PATH, show the copyable command instead of crashing.
- `c` copies the resume command (pbcopy / wl-copy / xclip / clip.exe, whichever exists) and flashes `copied`; if none exists, print the command on exit. `o` starts the web server if needed and opens the transcript page for that session.
- Tab cycles keyword → semantic → hybrid. If embeddings are missing, switching asks once: `Semantic search needs a one-time ~25 MB model download and a few minutes of indexing. Continue? (y/n)`, then shows progress `Embedding 1240/7864` and stays cancellable with Esc (progress is kept). If the optional dependency is missing, show the one-line install instruction.
- Keys are always printed on the bottom line. Esc or Ctrl+C quits and always restores the terminal (cursor, raw mode), including on errors.
- Letter keys `c`/`o` must not steal typing: they act only when the query is empty **or** with a modifier — use `Ctrl+Y` copy and `Ctrl+O` open as the always-available bindings, and show those in the footer. (Footer text: `⏎ resume  ^Y copy  ^O browser  ⇥ mode  esc quit`.)

## Phase 2b — Web UI (`src/web/`)

- `session-finder web [--port 4777] [--no-open]`. Binds `127.0.0.1` only. Reject any request whose `Host` header is not `127.0.0.1:<port>` or `localhost:<port>` (DNS rebinding guard). No CORS headers. Strict CSP (`default-src 'self'`), no external assets, no inline event handlers. If the port is busy, try the next 10 ports. Read-only JSON API:
  - `GET /api/search?q=&mode=&cwd=&since=&until=&role=&limit=` → `SessionResult[]` (empty `q` = recent sessions)
  - `GET /api/sessions/:id` → session meta + all indexed messages (paginated by `?offset=&limit=`)
  - `GET /api/folders` → distinct cwds with session counts
  - `GET /api/status` → counts, embedding progress, available modes
  - `POST /api/embed` → start/continue semantic indexing (requires a same-origin `Origin` header); progress via `/api/status`
- All transcript text is rendered with `textContent` / escaped. Transcripts contain arbitrary HTML and script-looking text; an XSS here exposes every secret in the user's history. Highlights are built from the structured `highlights` ranges, never by injecting HTML from the server.
- Page 1, search: a single focused search box, centred, nothing else above the fold until results exist. Results as cards: title, folder, age, match count, source badges in hybrid mode, snippet. Mode toggle (keyword / semantic / hybrid) next to the box; semantic options are disabled with an "Enable semantic search" button when embeddings are missing, showing progress once started. Folder dropdown and date range sit behind a small "Filters" control. `/` focuses the box, ↑/↓ + Enter navigate. URL reflects state (`?q=…&mode=…`) so back/forward and refresh work.
- Page 2, transcript reader (`/s/:id?m=<messageId>`): header with title, folder, dates, branch and one primary button "Copy resume command". Conversation as left-aligned message blocks, You vs Claude clearly distinguished, scrolled to and gently highlighting the matched message. Long messages collapse after about 30 lines with "show more".
- Visual rules (from Marc Lou's design series, adapted to a tool UI):
  - Four colours only: Base, Base Content, Base Content Secondary (metadata, folder paths, timestamps), Primary (the single main action per page: the copy-resume button; also match highlights). No pure black; dark mode via `prefers-color-scheme` using the same four roles.
  - 4-point spacing grid. Define at most six spacing tokens as CSS variables and use only those. Related things sit close (title to snippet 8px), unrelated far (card to card 24px+). When in doubt, more whitespace.
  - Body text 16px / weight 400 / line-height about 1.6, left-aligned, max line width about 680px for transcript text. Emphasis with weight 500–600, not extra colours.
  - One headline per view, bold and tight (letter-spacing slightly negative, line-height near 1). One primary button per view; everything else is secondary/ghost.
  - System font stack, monospace only for paths, ids and commands. Works down to 360px wide.

## Out of scope for v1

Subagent transcripts, stitching `continued-in` chains, API-based embeddings, any network call other than the one-time model download, telemetry, editing or deleting transcripts. The tool is strictly read-only on the Claude directory.
